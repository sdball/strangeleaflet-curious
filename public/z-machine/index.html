The Cabinet of Curios

The Z-Machine and how it runs stories

In 1979, two of the people bringing Zork to home computers invented a computer that didn't exist, so their story games could run on all the computers that did. Their games became story files: programs for that imaginary machine. This page opens one and takes it apart, from its header to its dictionary to its tree of rooms and things, draws a map of its rooms, reads out every string, decodes its code, and runs it up to the first prompt.

The page starts with After Hours at the Cabinet, a small game written for this page and short enough to read through. Press Zork I, Zork II, or Zork III to switch to one of Infocom's real games, built from its own source. You can also open a story file of your own, or drop one anywhere on the page, and every station will analyze that one instead. Buttons show their keys, like N for next and B for back, and the keys work on whichever station you're looking at.

All analysis is done locally in your browser. Your file never leaves your computer. To play a story instead of taking it apart, open it in the Z-Machine Interpreter.

Station 1

One story file, many machines

Zork was written at MIT in MDL, a language a lot like Lisp, on a DECsystem-10 mainframe, and it took up most of the memory a program could have there. Its authors wanted to sell it for home computers with far less memory than that, and there were many kinds of home computer, none of which could run another's programs.

First they cut MDL down to the parts Zork used and called the result ZIL, the Zork Implementation Language. That wasn't enough: compiled straight into any home computer's machine code, Zork would still have been too big. So in 1979 Joel Berez and Marc Blank designed a computer of their own, made for adventure games and nothing else: the Z-machine. It has its own compact machine code, Z-code. A game becomes a story file of Z-code, and each real computer gets a small program, an interpreter, that pretends to be a Z-machine and runs it. Infocom called theirs ZIP.

That paid off twice. Z-code is small: Zork's parser, the part that reads your sentences, took 10K 36-bit words on the mainframe and only 3K bytes as Z-code, and it did more. And a new computer needed only a new interpreter. After the first two, for the TRS-80 Model I and the Apple II, Infocom wrote interpreters for nearly twenty more computers and systems between 1982 and 1985, and a game written once could ship for all of them.

The interpreter also does the things that differ from screen to screen. The story file stores this description as one long line, and the interpreter folds it to fit whatever screen it's running on. Drag the width and watch it fold.


      

    

  


  
  

    

      
Station 2

      
The header

      
An interpreter starts by reading the first 64 bytes, the header. It says which version of the Z-machine the game needs, where each of the game's tables begins, and how to check the file isn't damaged. Pick a row to light up its bytes, or press N and B for the next and previous field. Addresses and bytes are in hexadecimal, written with a $.

Faded bytes are left for the interpreter to fill in when it starts: its own name, the screen size, and so on.

      

    

    

  


  
  

    

      
Station 3

      
Three kinds of memory

      
The header splits the file three ways. Dynamic memory holds everything that changes as you play: where each thing is, what's open, the score. Static memory holds tables the game reads but never changes. High memory holds the game's routines and most of its text. An interpreter has to keep dynamic and static memory in RAM, but high memory can stay on the disk and be read a page at a time. Pick a part to see where it sits, or press N and B to go through them in order.

    

    
    
    
    
    
  
    

  
  
    
    
    
      
    Station 4
    
      
    Three letters in two bytes
    
      
    Text is most of a story file, so it's packed. Each pair of bytes holds three 5-bit Z-characters, and the top bit marks the last pair. Five bits only count to 31, so three alphabets share them: lower case, capitals, and punctuation. A shift character switches alphabet for one letter, and a pair of Z-characters can stand for a whole abbreviation, a common run of text stored once. Step through a string and watch it come out.

    Station 5
    
      
    The dictionary
    
      
    Every word the game understands is listed here, packed the same way as text and sorted. When you type a command, the interpreter splits it into words, packs each one, and looks it up. The rest of the parser is the game's own Z-code. Version 3 keeps only six Z-characters of a word, so the first six letters are all that count. Press F to find a word.
    
    
    
    
    
      
      
      
    
    
    
    
    
    
  
    

  
  
    
    
    
      
    Station 6
    
      
    Rooms and things: the object tree
    
      
    Every room, thing, and person is an object, and objects nest. Each one records its parent, its next sibling, and its first child, so the whole world is one tree. Picking up the lantern is a single instruction that moves it from the room to you. Each object also has 32 on-off attributes (48 from Version 4) and a list of properties: its description, the words that name it, its exits, and anything else the game needs. Station 7 follows the exits from room to room.
    
      
    Press N and B for the next and previous object, and P for the one holding it.
    
    
    
    
    
      
      
      
      
    
      
    
      
  
      

  
      
    
      
      
      Station 7
      
      
      The map, as best the file can tell
      
      
      An exit is just a property. A room's north exit holds the room you reach by going north, a message saying you can't, or a routine that decides. Follow every exit and you have the map. Where a routine decides, the page reads it for the rooms it can send you to. Nothing in the file says where a room sits on the page, though. So this map is a guess: each room goes one step in the direction of the exit that reaches it, or to the nearest free spot when that one's taken. Games bend space, with passages that curve and mazes that loop, so expect some lines to cross.
      
      
      Pick a room on the map or from the list below it. Press N, S, E, W, U, D, I, or O to walk, as you'd type in the game. With the map focused, the arrow keys walk too.

      Station 8
      
      
      Every string in the file
      
      
      Text sits in two places. Most of it is inside the code: a print instruction carries its text packed right after it, so reading a game's prose means reading its routines. The rest is packed one string after another in the strings area after the code, where a routine or a property points at it by address. This station reads every routine and every packed string, so you can search them all.
      
      
      Type a few words to find text, even misspelled. ↑ and ↓ move through the matches, reading each one as you go. Back and Next read the whole file in order, and F jumps to the search.
      
    
      
    
      
    
      
      
      
        
        
        
      
        
        
      
        
      
        
        
        
        
        
          
          
          
        
        
        
        
      
        
    
        
  
        

  
        
    
        
      
        Station 9
        
      
        Routines: the code itself
        
      
        The game is a set of routines. Each starts with a byte saying how many local variables it has, 0 to 15, then its instructions. An instruction is an opcode saying what to do, its operands, and sometimes a variable to keep the answer in, or where to go next depending on whether the answer was yes. This station decodes them a routine at a time, starting with the one the game starts in. Station 10 runs them.
        
      
        Follow a call to read that routine, and Back B to come back. Next N and Previous P read the routines in the order they sit in the file, Start S returns to where the game begins, and G goes to an address.
        
    
        
    
        
      
      
      
      
      
        
        
        
      
        
    
        
    
        
    
        
    
        
      
          
      
          
    
          
    
          
  
          

  
          
    
          
      
          Station 10
          
      
          From the first byte to the first prompt
          
      
          Everything the earlier stations took apart, an interpreter puts to work in a moment when you open a game. Step through it: the version, the memory, the header bytes the interpreter fills in, then the game's own instructions, one at a time, until the game stops and waits for you to type.
          
      
          Step N goes forward a stage, then an instruction. Next text T runs until the game prints something, and To the prompt E runs until it waits for you. Back B and Start over S go back.

          Things to notice
          
    
            
      
          • A story file keeps numbers, not names. In the source, the front steps are FRONT-STEPS and the lantern is lit with ONBIT. In the file they're object 26 and attribute 7. The names on this page come from the listings the compiler wrote while building After Hours and the three Zorks. Most other files show numbers, which is all an interpreter needs. Games built with Inform 6 are the exception: they carry their property and attribute names, so they can print them in error messages, and Station 6 reads them.
            • 
      
          • An odometer and an odometry are the same word. Version 3 keeps six Z-characters of each word, so both pack to odomet. Type examine odometry in the game and it examines the odometer.
            • 
      
          • A saved game is small. Everything the game can change lives in dynamic memory, so a save only needs that, plus the interpreter's own place in the program. Station 3 shows how much of the file that is.
            • 
      
          • The interpreter doesn't know English. It splits what you type into words and looks them up in the dictionary. Working out what put the crank in the socket means is Z-code in the story file, so every game brings its own parser. After Hours borrows the one in ZILF's library. The Zorks carry Infocom's, in gparser.zil, which Infocom copied from game to game and changed as it went: Zork II's and Zork III's are the same file line for line, and Zork I's differs from them in a few dozen lines.
            • 
      
          • An Inform game starts in two instructions. Open Photopia, Lost Pig, or The Dreamhold and Station 9 shows the same start: call the main routine, then quit. The quit is only there in case the main routine ever returns, and in a working game it never does. ZIL games put their setup right in the first routine, so After Hours starts by printing its opening.
            • 
      
          • Some games take a hundred times longer to say hello. In the games tried while building this page, ZILF's reached their first prompt in a few hundred instructions, and Inform's took from about 2,000 to nearly 40,000. Station 10's breakdown shows where they go. Lost Pig, for one, reads the found_in property 1,080 times across its 535 objects before the game prints a word, checking which things are found in more than one place.
            • 
      
          • Nothing marks a room as a room. The format has objects and nothing else. Infocom's games, and ZILF's, keep every room as a child of one object, here called ROOMS, and a room is an object found there.
            • 
      
          • The same source can make a different file. Beside Zork's source on GitHub sits the story file Infocom shipped, release 119, which its own compiler, ZILCH, built in April 1988. The Zork I here was built by ZILF from that same source. Both files have 250 objects, but they're numbered differently: object 1 is the forest in Infocom's file and the pair of hands in this one, and only one object has the same number in both. So the names this page knows only fit the files it built.
            • 
      
          • Infocom's compiler forgave a slip. In Zork II's DREARY-ROOM-FCN, a bracket closes a COND one line early, so its last clause, (T <PCHECK> <RFALSE>), falls outside it. ZILF stops there. Infocom's ZILCH kept going, and the assembly it wrote, kept beside the source, shows it compiled the stray clause as two plain steps: call PCHECK, then return false. That's just what the routine does with the bracket where it belongs, so the Zork II here was built with that one bracket moved, in a copy. The source shown here is as Microsoft released it.

          A little history
          
    
            
      
          • Zork on a mainframe. Tim Anderson, Marc Blank, Bruce Daniels, and Dave Lebling wrote the first Zork on a DECsystem-10 at the MIT Laboratory for Computer Science, in MDL. A later translation into Fortran ran on DEC's PDP-11. Both versions were large: the first took most of the memory one program could have on its machine.
            • 
      
          • A machine designed on a coffee table. Joel Berez and Marc Blank designed the Z-machine in 1979, in Pittsburgh, according to the Standard's preface. Its first version, finished that autumn, already had nearly all of the design this page takes apart.
            • 
      
          • The first two interpreters. Scott Cutler wrote ZIP for the TRS-80 Model I, and Bruce Daniels wrote it for the Apple II.
            • 
      
          • Explained in a magazine. In July 1980, Blank and S. W. Galley described the whole design in Creative Computing, under the title "How to Fit a Large Program Into a Small Machine". The article opens on a transcript whose banner reads Zork: The Great Underground Empire, part 1, release 1. It gives the parser figures, explains the paging, and works out that packed text costs about five and a half bits a character instead of eight.
            • 
      
          • Version 3 for most of the decade. The first Version 3 game, Deadline, shipped in March 1982, and the last, a cassette sampler of Zork for the Commodore 64, in November 1987. Versions 4, 5, and 6 added bigger games, more screen control, and graphics.
            • 
      
          • New games for an old machine. From 1993, Graham Nelson's Inform let people outside Infocom compile story files of their own, and very many have been written with it since. A standard describing the machine exactly, so every interpreter would agree, was first drawn up in 1995, and version 1.1 was published in 2014. ZILF, a modern compiler for Infocom's own language, built After Hours for this page.
            • 
      
          • Zork's source, opened. In 2025 Microsoft released the source of Zork I, II, and III under the MIT License. It's a copy of Infocom's own files, kept as they were when the company closed. ZILF compiles Zork I's and Zork III's unchanged, and Zork II's with one bracket moved, and that's how the three Zorks on this page were made.
